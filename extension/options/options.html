    Storage status: checking…

    Settings not surviving a Firefox restart? This add-on uses the stable ID graphite-sider@local (manifest browser_specific_settings.gecko.id). Durable storage requires a permanent install: temporary installs via about:debugging are removed by Firefox at restart including their storage, and no extension code can prevent that. For an unsigned build, install the XPI permanently in Firefox Developer Edition, Nightly or ESR with xpinstall.signatures.required set to false in about:config (or use a signed build). Until then, use Export all settings below as a backup and re-import after reinstalling. Saves are written to browser.storage.local and verified by read-back; a backup mirror is also kept so a lost primary copy can be recovered automatically on next load.

    Exported settings files contain your API keys in plain text. Keep them private and delete them when no longer needed. Importing replaces your current providers, defaults and custom prompts.

    Security & privacy

    • API keys are stored in browser.storage.local on this device, with a recovery mirror in the extension's local storage and a size-capped settings-core mirror in browser.storage.sync (history is never mirrored to sync). They are sent only to your configured provider. Use Export/Import in Data to move or back up settings; exported files contain keys in plain text.
    • Keys are sent only to the baseUrl of the provider you configured, as part of that provider's API requests. Check the URL before pasting a key.
    • Local providers (Ollama, LM Studio) need no API key — leave the key field blank.
    • Page text, selections, subtitles or files you ask about are sent to your configured provider so it can answer. Nothing is sent to the Graphite Sider authors; there is no Graphite account or telemetry server.
    • Firefox host permissions: reaching http://localhost:11434 (Ollama) or http://localhost:1234 (LM Studio) requires host permission for localhost. If a local provider fails to connect, check that Firefox was granted permission for localhost / <all_urls> in about:addons → Graphite Sider → Permissions, and that the local server is running.
    • Use a separate, revocable API key for this extension where the provider allows it, and rotate keys you have shared in exported settings files.

    Help

    Getting an OpenAI API key

    Sign in at platform.openai.com, open API keys, create a new secret key, then add an OpenAI provider here, paste the key, pick a model (e.g. gpt-4o-mini) and click Test Connection. API billing is separate from a ChatGPT subscription.

    Getting an Anthropic API key

    Sign in at console.anthropic.com, open API Keys, create a key, then add an Anthropic provider, paste the key and pick a Muse model. Anthropic requests go to https://api.anthropic.com with the x-api-key header; Test Connection verifies it.

    Running Ollama locally (no key, private)

    Install Ollama from ollama.com, pull a model such as ollama pull llama3.1, and add the Ollama local provider (base URL http://localhost:11434, model = the pulled model name). Browsers block cross-origin calls by default, so start Ollama allowing extension origins:

    OLLAMA_ORIGINS=* ollama serve

    On Windows, set the OLLAMA_ORIGINS environment variable to * and restart Ollama. Then use Fetch models / Test Connection here.

    Running LM Studio locally

    Install LM Studio from lmstudio.ai, load a model, open the Local Server tab and start the server (default http://localhost:1234/v1) with CORS enabled. Add the LM Studio local provider, leave the API key blank, and use the model identifier shown by LM Studio.

    Sidebar on the right side

    Firefox controls the built-in sidebar position; extensions cannot set it (the sidebar_action API has no side option and extensions cannot change Firefox preferences). Open the sidebar, then use the sidebar header menu / View → Sidebar position to move it to the right, or set sidebar.position_start to false in about:config and restart Firefox. Firefox remembers the side for this profile. See Features → Sidebar position.

    Settings / API keys lost after restarting Firefox

    A temporary about:debugging install is removed at restart together with its browser.storage.local data — this is Firefox behaviour, not a settings bug, and no extension code can persist across it. Install the XPI permanently instead: Firefox Developer Edition / Nightly / ESR with xpinstall.signatures.required=false (unsigned builds), or a signed build in regular Firefox. The add-on's stable ID (graphite-sider@local) keeps its storage across restarts once permanently installed. You can also Export settings (Data section) and Import them after reinstalling.

    OpenAI-compatible gateways (OpenRouter, Groq, DeepSeek, Together, Fireworks, Mistral, xAI…)

    Pick the matching preset so the base URL is filled in for you, paste that service's API key, then use Fetch models to list the models your key can access. For any other gateway, choose Custom OpenAI-compatible and enter its /v1 base URL.

    Graphite Sider is a bring-your-own-key sidebar. Your providers bill you directly, and your keys never leave this machine except to the provider you picked.
